# frontend/pc 的设计

本页写 PC 办公入口为什么这样设计：术语、规则、仓库结构、依赖、实现状态与未决问题。写给要修改它的人与 AI。怎样使用与部署在 `BRICKKIT.md`；代码在哪、怎样构建与测试在 `AGENTS.md`。

跨组件的规则在装配项目 be-assembly-standard：
- 协议 20（入口与页面模块、浏览器会话、权限缺件与错误的显示、断网草稿、旧客户端、多语言、浏览器安全，独立预期 UI01–UI31）；
- 前端技术栈（`docs/zh/04-foundations/04-frontend-stack.md`：Vue 3、Ant Design Vue、vxe-table、两层导航、四种页面模板、四项偏好、CSS 变量令牌、写法约定）；
- 边缘（`docs/zh/04-foundations/09-edge.md`）；线协议第 11 章（会话 Cookie、`BE-Request`、`BE-Polling`、`features`、公网前缀）、第 03 章（错误）、第 17 章（流程内核的决定入口与原因）；
- 决定 D17（按入口选择与替换）、D24（断网草稿）、D34（按客户基线构建）、D61（服务端会话、边缘缓存令牌）、D68（待办的动作直发所属组件）、D82（每个持有者固定的“本人”段）。

首批范围是装配项目重建阶段 C12 的子计划定的；标“AI 定”的是重建时 AI 做的选择，待维护者复核。

## 边界

浏览器里的 PC 入口：外壳（登录态、服务选择器、菜单、标签页、命令面板、组织与法人切换、偏好）加按组件分的页面模块。它不是业务权威：每个规则、每次授权都在后端。

| 不在这里 | 归谁 | 为什么 |
| --- | --- | --- |
| 令牌、刷新、会话 | 身份成员持有会话；边缘缓存令牌并注入（D61） | 页面脚本拿不到令牌，跨站脚本偷不走 |
| 结束身份提供方的会话（登出后不被静默再登录） | 身份成员（FP06） | 只有它知道身份产品怎样结束会话 |
| 金额、库存、状态迁移等规则 | 属主组件 | 前端只管表单交互；要实时估算时调属主的试算接口 |
| 谁能看哪些行与字段 | 属主组件（按授权视图） | 前端只按答复显示，被屏蔽的字段按 `_masked` 显示 |
| 这个用户持有哪些操作 | 授权组件（FP05） | 它持有全部授予，算法与发给成员的视图同源 |
| 部署装了什么 | 装配工具生成 `features`、边缘提供 | 一套部署一个客户；未登录的拿不到 |
| 移动端 | `frontend/mobile` | 两种产品，只共享设计令牌的种子值 |

## 术语

| 叫法 | 定义 | 代码标识符 |
| --- | --- | --- |
| 入口 | 本仓库构建出的一个静态网站，按一个客户基线组合 | `shell` |
| 页面模块 | 一个后端组件在 PC 入口上的一组页面，带声明（FP02） | `modules/<组件>`，声明文件 `module.ts` 的 `definePageModule` |
| 客户基线 | 选中的组件与精确版本；本仓库的组合基线是仓库里的 `baseline/standard.yaml`（FP03） | `baseline` |
| `features` | 这个部署实际启用了什么：组件、版本（将来加能力）；装配工具生成，边缘只给已登录的会话 | `GET /api/features` |
| `permissions` | 这个用户此刻持有的操作键，只用于显示（“可能可以”） | `GET /api/authz/me/operations`（FP05） |
| 登录门槛 | 外壳启动时取一次 `features`：答 401 就是没有活着的会话 | `useSession().gate()` |
| 页面模板 | 列表、详情、表单、设置四种，页面从其中一种开始 | `ui-kit-pc` 的 `BeListPage` 等 |
| 运行时配置 | 部署给的品牌与开关，静态服务启动时写成 `/config.json` | `useRuntimeConfig()` |

## 规则

### 结构与组合

| 编号 | 规则 |
| --- | --- |
| FP01 | **仓库与包**：一个仓库、pnpm 工作区。`packages/ui-kit-pc`（第三方 UI 只出现在这里：Ant Design Vue、vxe-table、ECharts 的封装、四种页面模板、设计令牌与主题、导出与富文本的安全封装），`packages/api`（从各组件发布的 `contract/openapi.yaml` 生成的类型与客户端），`packages/shell`（外壳应用与会话、错误、草稿、格式的组合函数），`modules/<组件>`（页面模块，每个后端组件一个包），`packages/build`（按客户基线组合）。页面模块只引用 `ui-kit-pc`、`api` 与 `shell` 暴露的组合函数；页面里不引第三方 UI（lint 强制） |
| FP02 | **页面模块的声明**：`definePageModule({ component, contract: <主版本>, needs: [<组件>…], capabilities: [<能力>…], optional: [<组件>…], domain, menu: [{ key, route, title, operation }], routes, messages, drafts })`。`contract` 是所需的契约主版本，等于该组件发布版本的主版本（协议 19：契约在主版本内只追加）。`capabilities` 取自安全 09b 的能力目录，首批的模块都不需要。`operation` 是这个菜单项要的操作键。`optional` 里的组件缺席时由页面自己降级（例如隐藏一个标签页），用 `useFeatures().has(<组件>)` 判断。`drafts` 见 FP13 |
| FP03 | **按客户基线组合**（D34；AI 定）：组合用的基线是仓库里的文件 `baseline/standard.yaml`（装配项目标准基线的副本，随本组件的版本一起发布），与外壳的成员清单一样是源码的一部分：一个版本只出一个镜像，版本号不复用。`packages/build` 只把 `component` 与 `needs` 全在基线里、契约主版本相符的页面模块编进去，生成 `modules.generated.ts`，没编进的模块连代码都不在产物里；生成的文件列出编进与没编进的模块及原因。客户的基线不同（少装或换了组件）时，像客户的外壳一样 Fork 本仓库、改基线文件、发自己的版本；只少装几个组件的客户也可以直接用标准版本，没装的由运行时过滤隐藏（FP04） |
| FP04 | **运行时的过滤**：菜单项要同时满足：所属页面模块编进了产物；`features` 里有 `component` 与全部 `needs`（`features` 带能力之后再加 `capabilities`；部署可能与构建的基线不同，以部署为准）；`permissions` 里有这个菜单项的操作键。只查 `features` 不查 `permissions` 是易错点（协议 20）。隐藏不是安全边界：后端照样拒绝。`features` 答 401 走 FP06 的“需要登录”；答 503 时外壳只显示可重试的提示与不依赖组件的页面（偏好、已登出），不显示任何页面模块的菜单 |
| FP05 | **`permissions` 的来源**（源头补齐，AI 定）：授权组件新增一条普通的读取 `GET /api/authz/me/operations`，有自己声明的操作 `infra.authz.security_record.own_operations`，满足 P8.7。谁都不授予它：像 D82 的“放弃自己的记录”一样，授权组件给每个持有者（有授予或管理持有的账号）放一个固定的“本人”段（原子 `self`）。答复是调用者此刻持有的操作键：与授权组件发给各成员的视图同一套算法（角色修订仍有效、任职绑定成立、治理单元上限、键已登记未退役且仍被定义、处置未暂停、账号未停用），在任何一条有效段里出现的键都算；不带记录的事实，不按法人或维度筛，所以它只说“可能可以”，切换法人不重取。这条读取进授权槽位族的标准契约，移动端与 bff 也用它。答复的分类：200 是持有的键（没有任何授予的调用者得到空集）；503（视图过期、暂时无法证明）保留上次的结果并显示可重试，没有上次的结果时不显示任何页面模块的菜单，不显示为“无权”。重取：登录门槛之后取一次；之后每 5 分钟与窗口重新获得焦点时带 `BE-Polling: 1` 重取（页签隐藏时不轮询）；任何请求答 403 时重取，30 秒内最多一次 |

### 会话、请求与错误

| 编号 | 规则 |
| --- | --- |
| FP06 | **会话**：页面从不碰令牌。所有请求同源、带 Cookie；改变状态的请求带 `BE-Request: 1`（P11.2），轮询与定时刷新（角标、`permissions`、`version.json`）另带 `BE-Polling: 1`（P11.7），页签隐藏时停。<br>**登录门槛**：外壳启动先 `GET /api/features`；401 就整页跳到 `/api/iam/login?return_to=<编码后的路径与查询串>`（history 路由，片段不带；身份成员只接受以 `/` 开头、不以 `//` 开头的路径）。<br>**需要登录**：任何请求答 401，原因是 `SESSION_ENDED`（边缘：会话已结束）或 `TOKEN_INVALID`（没有 Cookie：别的标签页已登出）：清掉浏览器状态（FP13 的例外保留），跳登录，带当前路径。经边缘收不到 `TOKEN_STALE`（边缘重换重放，P11.3）；`DEPENDENCY_UNAVAILABLE` 与别的 503 显示可重试，不跳登录。<br>**登出**：`POST /api/iam/logout`（带 `BE-Request`），成功或答 401 之后：用 `BroadcastChannel('be-session')` 通知其他标签页，清掉 `permissions`、`features`、请求缓存、列状态以外的会话数据与草稿（FP13 的例外保留），进外壳的“已登出”页（不发任何 API 请求，只有“重新登录”）。登出后不被身份提供方静默再登录是身份成员的义务（`iam-casdoor` 3.0.59：Casdoor 的登录应用不开登录会话，A178）。<br>**边缘的布局**：`/` 的静态站不挂 be-edge 中间件；`/api/` 下全部挂。会话结束后浏览器留着的 Cookie 不能挡住再登录：边缘答 `SESSION_ENDED` 时清掉会话 Cookie，身份成员的登录与回调路径带着 Cookie 也照公开路由转发（P2 补进线协议第 11 章与 be-edge） |
| FP07 | **生成的客户端**：`packages/api` 用 openapi-typescript 从各组件的契约生成类型；请求只经外壳的 `request()`（不用 openapi-fetch：请求头、幂等键、重试与错误分类要在一处，P4 定）。外壳自己的三个平台请求（`features`、“我的操作”、登出）的组件没有发布用户面契约，按文档的形状手写类型。契约取自基线里的精确版本：脚本从各组件仓库的该版本标签取 `contract/openapi.yaml`，放进 `packages/api/contracts/<组件>/<版本>.yaml` 并提交，基线一变就重新生成，检查核对两边一致。一个包装（`shell` 的 `useApi`）统一加 `BE-Request`、按 FP08 把错误分类、带幂等键（写请求一个用户动作一个键，重试与查询都用同一个键）。只对读取（`GET`，本身幂等）与带幂等键的写请求自动重试可重试的错误（最多 2 次，按 `Retry-After`，没有时 1 秒、3 秒）；不带幂等键的写请求从不自动重放，显示“暂时无法确认”（协议 20、UI31）。页面里不手写 `fetch` |
| FP08 | **错误与缺件的显示**（协议 20 的表；文字按 `reason` 与 `metadata` 从语言资源取，不显示服务端的 `title`）：<br>看不见与不存在一样显示（`NOT_FOUND`，不泄露对象是否存在）；`PERMISSION_DENIED` 显示无权并重取 `permissions`（FP05）；校验失败按 `violations` 定位到字段；`AUTHORIZATION_UNPROVABLE`、`AUTHORIZATION_VIEW_EXPIRED`、`DEPENDENCY_UNAVAILABLE` 与别的可重试原因显示“暂时无法确认，请稍后重试”，有 `Retry-After` 时按它，不显示为无权或空列表；`CAPABILITY_UNSUPPORTED`（501）显示“这个功能需要后端升级”，不重试；`IDEMPOTENCY_IN_PROGRESS` 显示“处理中”，稍后用同一个键再查；`IDEMPOTENCY_KEY_REUSED` 是本入口的缺陷：记日志、显示失败、下一次动作换新键；结果未确认（超时、连接中断、待办直发的动作没有答复）显示“处理中，结果未确认”，“查询结果”用同一个幂等键重发同一个请求（SDK 原样返回原结果，`replayed`）；答复里的数据可能不完整（例如待办的 `stale`）时显示提示与截至时间；被屏蔽的字段按 `_masked` 显示“无权查看”，不显示为空；批量操作逐项显示成功、失败（原因）、跳过；**不认识的原因按保护处理**：显示“操作未完成”与原因代码，从不显示为成功 |
| FP09 | **待办的动作**（D68）：同意、驳回直接发到任务所属组件的决定入口，地址由任务的发布组件推出：`/api/<名字>/flow/tasks/{id}/decisions`（P17.14；名字是组件 ID 斜杠后的部分），不读投影里的地址；请求带幂等键与任务版本。决定的原因按 FP08 之外另加的文字显示：`VERSION_CONFLICT`、`TASK_NOT_PENDING`（任务已变，刷新待办）、`REVISION_CHANGED`（单据已改，打开单据看差异）、`SELF_APPROVAL`、`NOT_ASSIGNEE`、`NOT_QUALIFIED`（不能由你处理）、`QUALIFICATION_UNKNOWN`（暂时无法确认，可重试）。外壳不经统一待办转发，也不在本地把任务标成完成：等待办的下一次读取 |

### 导航、偏好与外观

| 编号 | 规则 |
| --- | --- |
| FP10 | **导航**：服务选择器按页面模块声明的领域分组、可搜索、最近访问、可加星标；收藏栏；组件内扁平菜单 3–5 项；应用内标签页（跨组件，未保存的表单离开前提示）；⌘K 命令面板（菜单项与最近的单据）；组织与法人切换器（只列 `mdm/org` 对本人可见的组织与法人；`mdm/org` 没装就不显示）。切换法人只是界面筛选：列表的法人筛选随之变、新建表单的缺省法人随之变；不是安全 06 的“选定的任职”，不改变授权（请求模式与选定任职见未决问题） |
| FP11 | **偏好**：收藏的组件与语言存身份成员的用户资料（首批：本地，资料接口另定，未决问题）；亮色、暗色、跟随系统与密度存本地；表格列状态只存本地。主色、logo、产品名、水印与灰度模式是**部署配置**：静态服务启动时把它们写进 `/config.json`（FP15），外壳启动时读，不在构建时注入 |
| FP12 | **设计令牌与主题**：Ant Design Vue 的 seed token 是唯一源头，`ui-kit-pc` 启动时由它派生 vxe-table 的 CSS 变量；亮暗与密度在一个函数里一起切换；部署配置的主色覆盖 seed 的主色。页面里不写颜色、尺寸与间距（lint 检查样式里的字面颜色与像素值）。种子值另存一份 `tokens/seed.json`，移动端照它（检查核对两边一致） |
| FP17 | **多语言与格式**（协议 20、UI16）：界面文本只在语言资源里（vue-i18n；lint 拒绝模板里的字面文字），首批 `zh-CN` 与 `en-US`，每种启用的语言都完整（检查核对键集合相同）。数据里的多语言文本由后端给默认名称与整组译文，前端按用户语言沿回退链选（用户语言 → 语言的主标签 → 默认名称）。数字与金额按用户语言的格式，金额的小数位按币种（ISO 4217 的小数位表放在 `shell`，三位小数的币种照样对）；金额与数量从不转成浮点计算，只格式化后端给的十进制字符串；业务日期原样显示；时刻按法人时区显示并标明时区（法人时区取自 `mdm/org`，没装时用浏览器时区并标明），用户偏好只改变显示 |
| FP18 | **列表的默认范围**：列表的默认读取范围由属主定（协议 11：未关闭，或最近 N 天内创建）；前端缺省不发日期范围，日期选择器的缺省显示为“默认（未关闭或最近 N 天）”，用户选了范围才发；不在前端另加一个更窄的缺省，也不缺省发“全部” |

### 草稿、版本、安全

| 编号 | 规则 |
| --- | --- |
| FP13 | **断网草稿**（D24）：一个组合函数 `useDraft(formType)`，存 IndexedDB，按入口、用户、法人、表单类型隔离；记表单的结构版本与所基于的记录修订；只存页面模块为这个表单声明的可进草稿的字段（`drafts` 的白名单），属主资源定义里的受限字段不在白名单里，除非资源定义声明允许；保留 7 天，每用户 5 MiB，超出时拒绝新存并提示；联网后由用户确认提交，提交时后端照常检查；修订变了显示差异；草稿从不显示为“已提交”。**登出时**：PC 默认保留本人草稿到过期（按用户隔离）；部署配置声明是共用终端时清除；任何时候，提交中、结果未确认的草稿连同它的幂等键都保留到结果确认或过期，本人下次登录时用同一个键查询（UI30）。首批接在采购申请的表单上 |
| FP14 | **写法**：`package.json` 写精确版本、锁文件进仓库；只用 `<script setup lang="ts">`（`eslint-plugin-vue` 的 `vue/component-api-style`）；`vue-tsc` 严格模式；大版本升级是单独的任务；依赖与版本记在下面的“依赖” |
| FP19 | **版本与旧客户端**（UI15）：构建产物带构建版本（`/version.json`，与本组件的版本相同，加构建的提交）；静态资源按内容摘要命名、长期缓存（`immutable`），`index.html`、`version.json`、`config.json` 不缓存（`no-cache`）。外壳每 5 分钟与窗口获得焦点时带 `BE-Polling` 取 `version.json`，部署的版本与自己不同就提示刷新（有未保存的表单时先提示保存）。后端为入口声明最低客户端版本的做法见未决问题 |
| FP20 | **浏览器安全**（UI17、UI18）：静态服务给每个页面发内容安全策略：`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'; form-action 'self'`。脚本只许本站、不许内联；样式许内联，因为 Ant Design Vue v4 的 CSS-in-JS 运行时插入样式（协议 20 只禁内联脚本），P4 用一个页面在这条策略下实测不报违规。富文本经 `ui-kit-pc` 的 `<BeRichText>`（DOMPurify 白名单）显示，首批没有富文本字段；用户上传的文件经附件组件的下载链接取，不内联。导出到电子表格只经 `ui-kit-pc` 的导出函数，以 `=`、`+`、`-`、`@`、制表符、回车开头的单元格加 `'` 前缀。外部链接与回调地址只用后端给的完整地址，前端不拼接 |

## 取舍

- **一个仓库多个包**：ui-kit、客户端与页面一起改、一起发；客户 Fork 入口时 Fork 一个仓库。拆成多个仓库要维护者新建仓库，也让一次改动跨仓库发版。
- **基线是源码的一部分**（FP03）：按部署的基线在装配时构建，同一个版本号会对应不同的产物，与“版本号不复用、构建跳过已有镜像”冲突；把基线放进仓库，组合与外壳的成员清单一样随版本走。代价：基线不同的客户要 Fork；只少装组件的客户直接用标准版本，靠运行时过滤。
- **`permissions` 放在授权组件、用本人段**：一次读取答全；它本来就持有全部授予，算法与视图同源。每个组件各开一条“我能做什么”要外壳调用一二十次，结果没有更准。用 D82 式的本人段，路由有自己声明的操作，不需要在线协议里另开一类“不要操作的路由”。
- **品牌在运行时配置**：前端技术栈把它定为部署配置；构建时注入会让同一版本对不同部署出不同产物。
- **样式许内联**：Ant Design Vue v4 的 CSS-in-JS 要插入样式；给样式发 nonce 要每个响应改写页面，静态服务做不到。内联样式的风险远小于内联脚本，协议 20 只禁后者。
- **静态服务用 nginx**：缓存头、history 回退、安全头、启动时用模板写配置都是现成的；它不是 SDK 组件，所以不进外壳、不读 SDK 的配置，只读自己的 `configSchema` 环境变量。

## 未决问题

- 用户资料（收藏、语言）存身份成员：资料接口另定，首批存本地。
- 请求模式（普通、代理、扮演）与安全 06 的“选定的任职”在浏览器请求里怎样表达：SDK 现在没有对应的请求头；首批只有普通模式，法人切换只是界面筛选（FP10）。
- 后端为入口声明最低客户端版本（协议 20）：放在哪里（例如 `features` 里）随第一个需要它的后端改动定；首批靠 `version.json` 提示刷新（FP19）。
- `features` 带能力（FP04）：be-ops 现在只出组件与版本，随第一个需要能力的页面模块补。
- 共用终端的短会话：随 `frontend/terminal`；PC 只有“共用终端”这个部署开关决定登出时清不清草稿（FP13）。
- 授权组件与身份成员没有发布用户面的 OpenAPI 契约：外壳的三个平台请求按文档手写类型（FP07）。
- 生产部署的边缘路由由装配工具从各组件的公网前缀生成（`docs/zh/04-foundations/09-edge.md`）；格里先由套件生成。
