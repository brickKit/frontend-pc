# frontend/pc 的设计

本页写 PC 办公入口为什么这样设计：术语、规则、仓库结构、依赖、实现状态与未决问题。写给要修改它的人与 AI。怎样使用与部署在 `BRICKKIT.md`；代码在哪、怎样构建与测试在 `AGENTS.md`。

跨组件的规则在装配项目 be-assembly-standard：
- 协议 20（入口与页面模块、浏览器会话、权限缺件与错误的显示、断网草稿）；
- 前端技术栈（`docs/zh/04-foundations/04-frontend-stack.md`：Vue 3、Ant Design Vue、vxe-table、两层导航、四种页面模板、四项偏好、CSS 变量令牌、写法约定）；
- 边缘（`docs/zh/04-foundations/09-edge.md`）；线协议第 11 章（P11.1–P11.11：会话 Cookie、`BE-Request`、`BE-Polling`、`features`、公网前缀）；
- 决定 D17（按入口选择与替换）、D24（断网草稿）、D34（按客户基线构建）、D61（服务端会话、边缘缓存令牌）、D68（待办的动作直发所属组件）。

首批范围是装配项目重建阶段 C12 的子计划定的（AI 定，待复核）。

## 边界

浏览器里的 PC 入口：外壳（登录态、服务选择器、菜单、标签页、命令面板、法人切换、偏好）加按组件分的页面模块。它不是业务权威：每个规则、每次授权都在后端。

| 不在这里 | 归谁 | 为什么 |
| --- | --- | --- |
| 令牌、刷新、会话 | 身份成员持有会话；边缘缓存令牌并注入（D61） | 页面脚本拿不到令牌，跨站脚本偷不走 |
| 金额、库存、状态迁移等规则 | 属主组件 | 前端只管表单交互；要实时估算时调属主的试算接口 |
| 谁能看哪些行与字段 | 属主组件（按授权视图） | 前端只按答复显示，被屏蔽的字段按 `_masked` 显示 |
| 菜单是否出现在部署里 | 构建时按客户基线组合页面模块（D34） | 没装的组件，页面根本不在构建产物里 |
| 移动端 | `frontend/mobile` | 两种产品，只共享设计令牌的种子值 |

## 术语

| 叫法 | 定义 | 代码标识符 |
| --- | --- | --- |
| 入口 | 本仓库构建出的一个静态网站，按一个客户基线组合 | `shell` |
| 页面模块 | 一个后端组件在 PC 入口上的一组页面，带声明（所需组件与契约主版本、菜单、路由、权限键、可选依赖、文本） | `modules/<组件>`，声明文件 `module.ts` 的 `definePageModule` |
| 客户基线 | 部署选中的组件与精确版本（装配项目的 `brickkit.yaml`） | `baseline` |
| `features` | 这个部署实际启用了什么：组件与版本；装配工具生成，边缘只给已登录的会话 | `GET /api/features` |
| `permissions` | 这个用户此刻持有的操作键（任何一条有效的授予段），只用于显示 | `GET /api/authz/me/operations`（FP05） |
| 页面模板 | 列表、详情、表单、设置四种，页面从其中一种开始 | `ui-kit-pc` 的 `BeListPage` 等 |

## 规则

| 编号 | 规则 |
| --- | --- |
| FP01 | **仓库与包**：一个仓库、pnpm 工作区。`packages/ui-kit-pc`（第三方 UI 只出现在这里：Ant Design Vue、vxe-table、ECharts 的封装、四种页面模板、设计令牌与主题），`packages/api`（从各组件发布的 `contract/openapi.yaml` 生成的类型与客户端），`packages/shell`（外壳应用与会话、错误、草稿的组合函数），`modules/<组件>`（页面模块，每个后端组件一个包），`packages/build`（按客户基线组合）。页面模块只引用 `ui-kit-pc`、`api` 与 `shell` 暴露的组合函数；页面里不引第三方 UI（lint 强制） |
| FP02 | **页面模块的声明**：`definePageModule({ component, contract: <主版本>, needs: [<组件>…], optional: [<组件>…], domain, menu: [{ key, route, title, operation }], routes, messages })`。`operation` 是这个菜单项要的操作键；没有它的菜单项不显示。`optional` 里的组件缺席时由页面自己降级（例如隐藏一个标签页），用 `useFeatures().has(<组件>)` 判断 |
| FP03 | **按客户基线组合**（D34）：`packages/build` 读客户基线（`BE_BASELINE` 指向一个 `brickkit.yaml`；没有时用仓库里的标准基线 `baseline/standard.yaml`），只把 `component` 与 `needs` 全在基线里、契约主版本相符的页面模块编进去，生成 `modules.generated.ts`；没编进的模块连代码都不在产物里。生成的文件列出编进与没编进的模块及原因 |
| FP04 | **运行时的过滤**：菜单项要同时满足：所属页面模块编进了产物；`features` 里有这个组件（部署可能与构建的基线不同，以部署为准）；`permissions` 里有这个菜单项的操作键。只查 `features` 不查 `permissions` 是易错点（协议 20）。隐藏不是安全边界：后端照样拒绝 |
| FP05 | **`permissions` 的来源（源头补齐，AI 定，待复核）**：授权组件新增一条读取 `GET /api/authz/me/operations`，答调用者此刻持有的操作键（任何一条在有效期内、在当前授权视图里可用的段），不带记录的事实，所以它只说“可能可以”；只给本人看，只要已核验的身份、不要操作（线协议补一类“本人的路由”）。外壳登录后取一次，之后在切换法人、收到 403 时再取 |
| FP06 | **会话**：页面从不碰令牌。所有请求同源、带 Cookie；改变状态的请求带 `BE-Request: 1`（P11.2），只为刷新角标的轮询另带 `BE-Polling: 1`（P11.7）；登录是整页跳到 `/api/iam/login?return_to=<当前路径>`，登出是 `POST /api/iam/logout` 后跳登录页。只有边缘答“需要重新登录”（401 且原因是会话已结束或令牌仍陈旧）时跳登录；“暂时无法确认”（可重试的 503）显示可重试，不跳登录 |
| FP07 | **生成的客户端**：`packages/api` 用 openapi-typescript 从各组件的契约生成类型，用 openapi-fetch 发请求；一个包装（`shell` 的 `useApi`）统一加 `BE-Request`、按协议 20 的表把错误分类（FP08）、带幂等键（写请求一个用户动作一个键，重试同一个键）。页面里不手写 `fetch` |
| FP08 | **错误与缺件的显示**（协议 20 的表）：看不见与不存在一样显示（不泄露对象是否存在）；校验失败定位到字段（`violations`）；“暂时无法证明”与“服务繁忙”显示可重试；结果未确认（超时、待办直发所属组件的动作没有答复）显示“处理中，结果未确认”并提供按幂等键查询；被屏蔽的字段按 `_masked` 显示“无权查看”，不显示为空；批量操作逐项显示 |
| FP09 | **待办的动作**（D68）：同意、驳回直接发到待办条目里的动作入口（组件 + 路径），带幂等键；外壳不经统一待办转发，也不在本地把任务标成完成：等待办的下一次读取 |
| FP10 | **导航**：服务选择器按页面模块声明的领域分组、可搜索、最近访问、可加星标；组件内扁平菜单 3–5 项；应用内标签页（跨组件，未保存的表单离开前提示）；⌘K 命令面板（菜单项与最近的单据）；法人切换（只列 `mdm/org` 对本人可见的法人，切换后列表的法人筛选随之变） |
| FP11 | **偏好**：收藏的组件与语言存身份成员的用户资料（首批：本地，身份成员的资料接口另定，未决问题），亮暗与密度存本地；表格列状态只存本地；主色、logo、产品名是部署配置（构建时的环境变量） |
| FP12 | **设计令牌与主题**：Ant Design Vue 的 seed token 是唯一源头，`ui-kit-pc` 启动时由它派生 vxe-table 的 CSS 变量；亮暗与密度在一个函数里一起切换。页面里不写颜色、尺寸与间距（lint 检查样式里的字面颜色与像素值）。种子值另存一份 `tokens/seed.json`，移动端照它（检查核对两边一致） |
| FP13 | **断网草稿**（D24）：一个组合函数 `useDraft(formType)`：按入口、用户、法人、表单类型隔离存 IndexedDB；记表单的结构版本与所基于的记录修订；受限字段不进草稿；联网后由用户确认提交，提交时后端照常检查；修订变了显示差异。草稿从不显示为“已提交”。首批接在采购申请的表单上 |
| FP14 | **版本与写法**：`package.json` 写精确版本、锁文件进仓库；只用 `<script setup lang="ts">`（`eslint-plugin-vue` 的 `vue/component-api-style`）；`vue-tsc` 严格模式；大版本升级是单独的任务 |
| FP15 | **部署**：一个 BrickKit 组件，镜像是静态文件服务（构建产物，没有服务端逻辑），在边缘后面挂在 `/`；没有健康检查之外的接口。`features` 不在本组件里：装配工具生成、边缘提供 |
| FP16 | **测试**：FE-1（组合函数、过滤、错误分类、草稿：网络替换掉）与 FE-2（`ui-kit-pc` 的模板与 `<BeTable>`）随代码写；FE-3（真实浏览器经边缘对真实后端，按业务流程命名）与 FE-4（FE-3 经过的关键页面的截图，亮暗各一）先问维护者再跑 |

## 取舍

- **一个仓库多个包**：ui-kit、客户端与页面一起改、一起发；客户 Fork 入口时 Fork 一个仓库。拆成多个仓库要维护者新建仓库，也让一次改动跨仓库发版。
- **`permissions` 放在授权组件**：一次读取答全；它本来就持有全部授予。每个组件各开一条“我能做什么”要外壳调用一二十次，结果与授权组件的视图同源，没有更准。
- **静态文件作为组件**：被客户基线选择、按版本升级，与后端组件一样；边缘只路由。

## 未决问题

- 用户资料（收藏、语言）存身份成员：资料接口另定，首批存本地。
- 共用终端的短会话与登出清理：随 `frontend/terminal`。
- 生产部署的边缘路由由装配工具从各组件的公网前缀生成（`docs/zh/04-foundations/09-edge.md`）；格里先由套件生成。
